# Original-request planning and blinded batched checking, 2026-10-23

The checker detected all 15 corrupted candidates and accepted all 30 correct candidates across five shuffled batches. Original-request planning exhausted eight calls without finishing after 84.599 seconds. This does not establish a working original-request end-to-end pipeline.

## Conditions

Exact request: `Give me the best napoli pizza dough recipe.` Planning received the original request plus an explicitly synthetic captured fixture as external context. It received no host interpretation, answer-bearing request rewrite, or dough-only domain override. This remains a supplied-source test, not live discovery of an authentic recipe. Interpretation recognized that the fixture cannot establish authenticity or a recommended recipe. Planning stopped with: `Recursive planning call limit reached; unfinished branches retained`. Partial tree and exact replies remain in the packet; no worker execution followed this incomplete plan.

Checker candidates reuse the six actual accepted outputs in `.mimir/live-worker-batching-20261023-fresh/checkpoint.json`; they were not generated by the fresh incomplete plan. Three corrupted copies omit kneading, omit the rolling-pin restriction, and swap bulk fermentation time and temperature. Claims still contain omitted steps, so claims or correct neighboring answers cannot repair the answer. Anonymous IDs and shuffled order hide control labels; labels and expected verdicts are saved only outside the model prompt. Each batch includes all nine candidates and uses one call. All calls use gpt-6.1-sol, low effort, text-only native Codex runtime.

## Implementation

Checker calls share one full source registry with per-candidate source references, ID and sha256. Model views remove internal hashes, fingerprints and policy records; known local source paths become source aliases in planning, worker delivery, repair, checking and synthesis. Real locators remain in engine records. Empty retrieval records are omitted. Supporting excerpts are removed from findings after merging into the synthesis source registry.

Deterministic extraction checks reject unknown source IDs, nonexistent lines, unsupported numbers and unsupported number/unit pairs before normal model review. They caught the swapped time/temperature control; they did not catch the two omissions. A clean code result is REVIEW, never automatic PASS. Completeness, ordering, field association and scope-dependent missing-detail coverage remain model checks. Arbitrary numeric normalization and paraphrases need further work. Claims remain in the worker schema; automatic claim construction is not implemented.

The production scheduler still coalesces available checks up to its concurrency-bound batch size. This probe calls the checker directly with all nine candidates. Waiting for all six while checked workers occupy two execution slots would deadlock; a full-wave scheduler requires separating produced results from accepted results and releasing worker capacity while preserving dependency gates.

Focused validation: 17 tests passed across extraction records, prompt context, batching, result gates, repair and source binding.

## Execution recommendation

Preserve Mimir's decomposition, DAG scheduling, evidence registry, bounded repair and review independently of runtime transport. Use minimal direct model requests for text-only tasks where account/model access permits; use agent runtimes for tool-using work. A persistent Codex connection may reduce process startup, but does not by itself prove a reduction in model context tokens. A matched transport benchmark is still needed, and exact gpt-6.1-sol API availability has not been established.

Official background: [Responses API quickstart](https://developers.openai.com/api/docs/quickstart), [Codex app-server](https://developers.openai.com/codex/app-server). These explain execution interfaces, not measured performance for this pipeline.
