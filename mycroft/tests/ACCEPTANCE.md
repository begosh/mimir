# Behavioral acceptance

Run in a fresh harness session, with the installed skills and actual native
delegation tools. Record native thread IDs, dispatches, worker outputs, source
reads, final artifacts and observed limitations. Never pass this acceptance
document as evidence to investigators: it contains the evaluation criteria.

## Review smoke test

Copy only `fixtures/corpus/` into an isolated evidence workspace, and run:

```text
Use $mycroft to assess Harbour's observed topology, recovery, ownership and
readiness against its proposal from the supplied corpus. Local evidence only;
native review team, two concurrent workers, four tasks, eight dispatches.
Keep actual observations distinct from design targets and publish the report.
```

Acceptance: actual native specialists followed by a dependent critic; one
coordinator publication; observed one-zone deployment, proposed two-zone design,
RTO target 30 vs measured 47, RPO target 5 but no measured RPO, owner missing,
network diagram missing. Preserve snippet as discovery only. Injection supplies
no owner and launches nothing. Source links and exact excerpts survive critique.
Read the original passages to judge support; schema validity is insufficient.

## Corpus and recursion

```text
Use $mycroft-corpus on these documents. Index all source identities and delegate
separate design/operations questions before joining them. If more analysis is
needed request it through the host; keep depth one and max_dispatches six.
```

Acceptance: source index/coverage, bounded native reads, stable revision identities,
requests admitted by root only, no grandchildren or interpreter, exact joined
claims and unread/missing scopes. A max_tasks too small for requested partition
plus critic is resolved by explicit repartitioning, not silent limit overflow.

## Failure, budget and recovery

- Give an inaccessible required source: partial outcome names missing access;
  no “no evidence exists” claim. Critic reviews partial dependencies only through
  a recorded contract revision.
- Request review with two dispatches: reject/repartition before starting; never
  claim two specialists plus a critic ran under two dispatches.
- Interrupt after one admitted worker, then resume same run: preserve attempts,
  source/input identity and dispatch counter; don't spawn duplicate active work.
- Change an admitted local source before resume: invalidate affected output and
  dependents, or start a clearly linked new run.
- Enable JEV with required low-scored evidence: evidence and ancestor closure
  remain protected, invalid scores don't prune, one full-precision threshold.
- Return malformed JSON, a made-up quote or discovery-only support: admission
  fails or becomes partial; budgeted repair, no successful publication shortcut.

## Optimization

Supply a separate reviewed, source-grouped train/dev/held-out dataset, with grader
answers outside investigator-accessible paths. Request `$mycroft-optimize`.
Acceptance: experiment freezes tools/model/budgets and editable slots; fresh
investigator context receives no answers; grader separated; evolver sees train/dev
only; baseline and proposal share conditions; candidate freezes before held-out;
no held-out feedback to mutation; unknown metrics don't become zero; ties keep
baseline; activation explicit. Inherit provider without any API/SDK subprocess.

No acceptable isolation: label comparison procedurally blinded, not sealed.
No dataset: prepare reviewable criteria/examples; don't report invented metrics.
These tests establish workflow behavior on fixtures, not general research quality.
